# 2D 画面量化对比脚本（FM26 Mobile vs VCFM）

诊断用，**不进 `verify.mjs`**。用于把「画面观感」变成可对账的数字，
避免 AGENTS.md 反复记过的教训：肉眼读静态帧会系统性误判。

## 依赖

Python 3 + OpenCV（`pip install opencv-python numpy`）。无需 scipy/sklearn。
本机实测环境：Python 3.13 + cv2 5.0.0。

## 标定（换素材必做，否则米制全错）

**不要用草皮包围盒换米。** 草皮画到边线之外——FM 的绿色区域宽高比 1.72，
而真实球场 105:68 = 1.54，差 11%，直接拿它换米会系统性偏大。

正确做法是用**白色标线**的行列投影定边线矩形（`cmp2b_diag.py` 打印剖面），
再用**真实禁区纵深 16.5m 交叉验证**：

| | 草皮盒 | 球场矩形（草皮盒内子坐标） | 长度轴 | 禁区验算 |
|---|---|---|---|---|
| FM26 | (212,114)-(1063,609) | x 38.5–810.5、y 16–475.5 | x（横屏） | 禁区线 x=160，距底线 121.5px；772px=105m → **16.5m** ✓ |
| VCFM | (48,150)-(573,937) | x 0–525、y 0–787 | y（竖屏） | 禁区端线 y=123.5 占全长 15.7% → **16.5m** ✓ |

草皮色相范围：FM `H∈[34,70]`、VCFM `H∈[52,88]`（`cmp1_recon.py` 自动找峰值）。

VCFM 禁区宽占 56.8%，真实是 59.3%——这是 v238 按引擎 `_inOwnFoulBox`（x 22–78）
重画标线的已知结果，不是新 bug。

## 两个必须知道的坑

**1. 必须剔除慢镜段，否则速度结论是伪影。**
VCFM 录屏有 **27.3%** 的帧处于持续低速段（慢镜回放、死球摆位、进球 hold）。
不剔除时位移中位 1.10 m/s，剔除后 **1.91 m/s**——夸大近一倍。
判定：每帧中位速度 <0.6 m/s 且连续 ≥4 帧（≥1 秒）。FM 同口径剔除 13.9%。

剔除后的 1.91 m/s 与 AGENTS.md v238 记的引擎内实测 **2.05 m/s** 相差 7%，
**两个独立测法交叉验证通过**——这是视频侧数字可信的依据。

**2. 分队不能用色相 2-means。**
把 H(0–179) 翻倍成角度后用 `(sin,cos,sat)` 聚类，VCFM 的橙红 H≈18(36°) 与
粉红 H≈167(334°) 的 cos 都接近 +1，被判成同一队（实测人数比 1311:19111，等于没分开）。
改用**色相直方图双峰模态 + 圆环距离分配**（`cmp5`/`cmp6` 的 `two_modes`），修正到 0.78。
脚本会打印分队人数比，**低于约 0.6 就不要采信依赖分队的指标**。

## 已知限制

- 球员检测不完整：FM 中位测到 14/22 人、VCFM 17/22。**比例与量级可信，绝对值不可当精确数。**
- 分队人数比 FM 0.73 / VCFM 0.78，未达理想的 1.0。
- `cmp8_ball.py` **一次都没跑成**（写完时权限分类器不可用）。逻辑未验证，
  首次运行请先看它自报的检出率与球速分布（球速应在 0–35 m/s；检出率过低或速度荒谬则不要采信）。
