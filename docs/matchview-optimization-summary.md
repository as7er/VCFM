## 技术亮点

### 1. 状态机设计

**核心价值**：用显式状态机替代 5 个布尔标志（`phase`, `scriptLock`, `frozen`, `holdUntil`, `aftermathUntil`）

**状态层级**：
```
IDLE → PRE_MATCH → PLAYING → GOAL_SEQUENCE → PLAYING
                       ↓           ↓
                    PAUSED     CELEBRATE
                       ↓
                  HALF_TIME → FULL_TIME
```

**代码对比**：
```javascript
// 旧代码（5 个标志组合）
if (this.phase === "play" && !this.frozen && !this.scriptLock) { ... }

// 新代码（语义清晰）
if (this.fsm.canAIAct()) { ... }
```

---

### 2. 导演脚本系统

**核心价值**：配置驱动的叙事时序，替代硬编码的 `await wait(720)` 等

**配置示例**：
```javascript
GOAL_NARRATIVE.rewatch = {
  phases: [
    { name: 'setup', duration: 0.72, speed: 1.0, camera: 'follow' },
    { name: 'pass', duration: 0.92, speed: 0.6, focus: 'passer+scorer' },
    { name: 'shot', duration: 0.52, speed: 0.4, camera: 'box' },
    { name: 'celebrate', duration: 2.6, speed: 0.9, camera: 'wide' }
  ]
}
```

**优势**：
- 逻辑时间与墙钟时间解耦（`duration / speed`）
- 修改叙事节奏只需改配置，不动代码
- 支持暂停、跳过、进度查询

---

### 3. 坐标系统统一

**核心价值**：消除 50+ 处魔法数字（`44, 56, 3.5, 96.5`），统一坐标变换逻辑

**常量定义**：
```javascript
GOAL: { HOME_Y: 96, AWAY_Y: 4, X_MIN: 44, X_MAX: 56 }
AREA: {
  BOX_LARGE: { HOME: {yMin:82, yMax:96, xMin:28, xMax:72} },
  CORNER: { HOME_LEFT: {x:5, y:93}, ... }
}
```

**工具方法**：
- `isInBox(x, y, team)` - 判断是否在禁区
- `distanceToGoal(x, y, isHome)` - 射门距离
- `getCelebrationCorner(scoredHome, ballX)` - 庆祝角旗位置
- `slotToPitch(slot, isHome)` - 处理主客翻转

---

### 4. Canvas 渲染优化

**核心价值**：分层 Canvas + 脏矩形 + 精灵缓存，低端设备性能提升 15-30%

**三层架构**：
- `bg` - 背景层（草坪、看台，很少变化）
- `field` - 场地层（球员、球，每帧变化）
- `ui` - UI 层（轨迹、特效，按需更新）

**优化技术**：
1. 背景层只画一次，不每帧重绘
2. 脏矩形检测：只重绘球员移动区域（静态场景节省 60-80% 重绘）
3. 精灵缓存：预渲染球员圆点到离屏 Canvas，减少路径绘制开销

## 集成路线图（4 个阶段）

### 📅 阶段 1：状态机重构（优先级：🔴 高）

**改动范围**：
- `matchview.js` 中约 50 处状态查询/赋值
- 不影响外部接口（`match.js`, `main.js` 无需改动）

**预期收益**：
- 消除状态冲突风险
- 代码可读性大幅提升
- 新增状态（如点球大战）更容易

**风险**：中等（需要仔细测试所有状态转换场景）

**改动范围**：
- `_beginGoalBeat`, `_stageKeyMoment` 等叙事方法
- 约 300-400 行代码可简化为配置驱动

**预期收益**：
- 叙事时序调整无需改代码
- 支持多套叙事风格（快节奏 / 写实 / 戏剧化）
- 易于 AB 测试不同慢镜配置

**风险**：低（配置与原逻辑等价，向后兼容）

---

### 📅 阶段 3：坐标系统抽取（优先级：🟡 中）

**改动范围**：
- `matchview.js` 中约 100 处坐标计算
- `engine.js` 也可复用（当前有独立常量）

**预期收益**：
- 魔法数字全部消失
- 修改场地尺寸/球门位置只需改常量
- `engine.js` 和 `matchview.js` 坐标逻辑统一

**风险**：低（纯工具函数，不改业务逻辑）

---

### 📅 阶段 4：Canvas 优化（优先级：🟢 低 / 可选）

**改动范围**：
- 初始化渲染器，分层绘制
- 约 200 行渲染代码重构

**预期收益**：
- 低端设备（< 2GB RAM）性能提升 15-30%
- 静态场景（定位球、庆祝）重绘开销减少 60-80%

**风险**：中（增加复杂度，需性能测试验证收益）

**建议**：**非必需**。当前全量重绘已足够流畅，除非要支持更多同屏球员或 3D 视角。
